# История изменений

Формат вдохновлён [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/).
У проекта пока нет тегов/релизов — записи сгруппированы по датам и темам, а не
по номерам версий. Полная детальная история — в `git log`.

## Не выпущено

### Добавлено
- Общий диагностический **PDF-отчёт** по выбранному подключению: размеры схем
  и крупнейших таблиц, активные запросы/сессии/блокировки, незавершённые
  транзакции, эффективность доступа к таблицам, статистика VACUUM/ANALYZE и
  заключение о производительности. Формируется в фоне, на русском или
  английском; история и скачивание — во вкладке «Настройки → PDF-отчёты»
  (фильтры, пагинация, автообновление).
- Незаблокирующее предупреждение Django-проверки (`db_statistics.W002`), если
  `SECRET_KEY` не задан явно — вместо жёсткого отказа в запуске.
- Subresource Integrity (SRI) для всех внешних CDN-скриптов/стилей
  (Bootstrap, Font Awesome, Chart.js).

### Исправлено
- `docker-entrypoint.sh` больше не добавляет флаги gunicorn к произвольной
  переопределённой команде (`manage.py check`/`shell` и т.п. работали
  некорректно).
- Некорректный `id`/`job_id` в запросе к API возвращал 500 вместо
  корректного 400/404 на ~30 эндпоинтах.
- Фоновые задачи обслуживания (VACUUM/ANALYZE) могли зависать в статусе
  «running» навсегда при ошибке, отличной от ошибки драйвера БД.
- Все 4 автообновляемых поллера (запросы/сессии/блокировки/транзакции)
  получили защиту от параллельных запросов — медленный ответ БД больше не
  приводит к нарастающей очереди запросов к пулу соединений.
- Экранирование текста ошибок сервера в нескольких обработчиках `home.js`,
  которые вставляли его в `innerHTML` без `escapeHtml()`.
- Восстановлен нормальный `.gitignore` (был перезаписан текстом-заглушкой) —
  `.env`, `db.sqlite3`, `__pycache__/`, `.idea/` теперь корректно игнорируются
  и не могут случайно попасть в коммит.
- `make migrate` (и инструкции в README) теперь используют
  `migrate --run-syncdb` — без этого таблицы `db_statistics` не создавались
  на чистой установке (приложение использует прямую синхронизацию схемы из
  моделей, а не миграции Django — см. `MIGRATION_MODULES` в `db/settings.py`).

### Удалено
- Мёртвый CSS: неиспользуемые правила под Bootstrap-компоненты, которых нет
  ни в одном шаблоне (`.dropdown-menu`, `.form-select`, `.input-group-text`,
  `.page-link`, `.table-hover`, `.progress`/`.progress-track`), и
  `.sidebar-language-setting`.
- Устаревшая прослойка `db_statistics/views/__init__.py`, реэкспортировавшая
  32 неиспользуемых имени — оставлено только то, что реально резолвится
  через `handler404`.
- Осиротевший файл `db_statistics/migrations/0001_initial.py`: с момента
  добавления `MIGRATION_MODULES = {"db_statistics": None}` Django его больше
  не читает — файл просто лежал мёртвым грузом.

## Ранее

- Общий PDF-отчёт по базе данных, перенос его в фоновые операции, отчёты по
  выбранному языку, фильтры/пагинация для истории отчётов (сентябрь 2026).
- Блокировка входа после серии неудачных попыток, аудит по действиям
  пользователей, избранные объекты, персональные настройки бокового меню.
- Разбиение `views/helpers.py` на модули по разделам интерфейса
  (`pool`, `auth`, `audit`, `pagination`, `maintenance`, `additional`,
  `administration`, `data`, `infrastructure`, `performance`, `reports`).
- Шифрование сохранённых паролей к подключениям, пул соединений psycopg2,
  ограничение частоты запросов для проверки подключения и запуска
  обслуживания.
